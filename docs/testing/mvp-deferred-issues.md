# Deferred MVP issues and test-drive checks

Remaining limitations and recorded live test evidence. Focused input fixes below supersede the initial typing, alias and attach-diagnostic findings.

- **Display sleep:** screenshots intentionally do not send input. A stable black image reports unknown readiness. Coordinator observed explicit Shift down/up waking the Windows desktop after a settling delay while SPICE remained connected. Recovery: send an intentional wake key, wait, and capture again. Confirm visually during acceptance.
- **Blocking libvirt calls:** screen polling deadlines bound the loop and sleeps, but a synchronous daemon call can exceed the requested timeout. A stalled daemon can also delay shutdown cleanup. Recovery: restore the daemon/connection or restart the local MCP process; no guest power operation occurs. Consider bounded transport/worker cancellation only if the test drive exposes a real stall.
- **Input device and layout:** absolute coordinates depend on an already configured absolute pointer; ANSI US physical keys depend on the guest's layout/IME. No device changes or calibration occur. Recovery: configure the existing guest in virt-manager and choose its layout manually. Test pointer alignment and representative punctuation in Windows.
- **External input and display changes:** human/SPICE input is not arbitrated, and a resize between coordinate validation and event delivery can shift the destination. Recovery: stop competing input and recapture current dimensions. Test viewer open/close and resizing without MCP reconnection.
- **Best-effort held-input release:** disconnects, guest shutdown or process termination can prevent cleanup. Detach reports `inputs_released=false` when it cannot release. Uncertain input is never retried automatically. Recovery: `qemu_release_all` while attached after reconnect, or release keys/buttons through the viewer. SIGKILL cannot run shutdown cleanup.
- **Local access:** monitor input and explicit power tools inherit the host user's libvirt permissions. Only trusted local MCP clients should use this controller. There is no per-tool authorization layer in this MVP. Use existing host access policy if stronger isolation is needed.
- **Graceful power:** shutdown/reboot are requests, not completion promises. A guest can ignore them. Recovery: inspect status and use explicit force stop only when intended. No automatic escalation or snapshot changes occur.
- **Visual acceptance remaining:** guest framebuffer tests and active SPICE connection checks passed. Host GNOME screenshot access was denied, so direct visual confirmation inside the virt-manager window, viewer close/reopen, resolution/scaling changes, and horizontal scrolling on an actual horizontal-scroll surface remain manual test-drive checks. Horizontal wheel events were accepted by QMP.
- **Concurrent attachment management:** input actions serialize per UUID, but simultaneous attach/detach calls are not a transactional registry operation. Recovery: reattach after a concurrent detach; prefer one attachment-management caller. Revisit only if parallel client workflows need that guarantee.
- **Very small color changes:** the retained framebuffer comparison converts RGB differences to luminance; low-intensity single-channel changes can round to zero. This can classify a nearly unchanged frame as stable. Readiness remains unknown. Recovery: inspect screenshots or use a stricter application-specific signal outside this MVP; evaluate exact channel comparison if this matters in the test drive.

- **Screen-wait interleaving (independent review):** wait_screen locks individual captures, not the entire polling loop. Concurrent MCP input can change the observed screen, and detach can interrupt a wait. Sequential calls work. Recovery: await the wait result before issuing another action. Decide whether observation should block input after the test drive; input actions themselves remain serialized per VM.
- **Last-detach connection retention (independent review):** detaching the final VM retains one shared libvirt connection for reuse until server shutdown. This does not accumulate connections or power off guests. Recovery: exit the MCP server to close it. Reconcile this with the original detach cleanup contract after the test drive.
- **Application focus:** Notepad's first-run account popup took focus during the initial live typing scenario and opened Edge links. After dismissing the popup and explicitly clicking the editor, text entry passed. Tool success means input delivery, not that the intended application received it. Capture and inspect focus before typing into a newly opened application.
- **Attach diagnostic noise resolved:** domain names now go directly to name lookup. UUID identifiers are validated/normalized before UUID lookup, retaining name fallback for UUID-shaped domain names. Candidate real-name MCP attachment succeeded without the previous `Invalid UUID` stderr warning.

- **Rapid repeated-key loss addressed:** the original rapid Shift+A/release+A probe showed one A. The focused baseline replay rendered Aa, so loss was intermittent. Shared pacing now separates release/next-press across calls; fake-clock regressions cover those boundaries and held modifier semantics. Candidate live repeated-key results are recorded below.
- **Right-Alt alias added:** `rightalt`, `ralt`, `alt_r` and `altgr` map to QEMU `alt_r`. Corresponding right Ctrl/Shift names are supported. Use `rightalt`, since `right-alt` still means a Right-arrow/left-Alt chord. Candidate live IME results are recorded below.
